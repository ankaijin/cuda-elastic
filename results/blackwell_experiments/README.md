## TMA tile loads and warp specialization (`tma`)

**Question.** Can changing tile loading reduce instruction overhead without changing attention arithmetic?

**Workload.** loom-private/multisensor-attention, optimized variant: 25,000 queries over 250,000 context tokens, 64 query rows per block, 1,024-key tiles, two shared buffers, 12 context splits.

| Case | Role | Description |
|---|---|---|
| `control` | control | applications/loom_private/attention/attention_optimized.cu unchanged: double-buffered cp.async tiles (16-byte copies by all 256 threads), block barriers before and after each tile |
| `tma` | candidate | attention_tma.cu, mode 1: thread 0 issues one cp.async.bulk per tile; all threads wait on the tile's mbarrier; a block barrier after each tile guards reuse |
| `tma_producer` | candidate | attention_tma.cu, mode 2: a ninth warp issues the bulk copies; compute warps wait on full mbarriers and release empty mbarriers; no block barrier inside the stream; two blocks per SM kept with __launch_bounds__(288, 2) |

### Conclusions

- `bf16`: **improved**.
- `mxfp6`: **improved**.
- `nvfp4`: **improved**.
- Speed: application-scope decode time falls to 0.27 (BF16), 0.15 (MXFP6), and 0.067 (NVFP4) of the FP32 control, in every pair.
- Accuracy on the dense fixtures: normalized RMS logit error about 0.23% (BF16), 7.7% (MXFP6), and 13.5% (NVFP4); four-step token agreement 247-256, 174-204, and 161-171 of 256. On the primary synthetic model every case agrees on all 4,096 tokens.
- Only the FP32 control and NVFP4 pass the production FP32 tolerance check of the primary decode. NVFP4 passes because its two-level scaling represents that synthetic model's values almost exactly; the fixtures show its general error.
- MXFP6 uses the OCP v1.0 shared exponent, which clips block maxima whose mantissa exceeds 1.75; this contributes to its error on the primary model (12.4%).
- Improved refers to speed only; whether the accuracy loss is acceptable depends on the application.

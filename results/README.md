# CUDA performance results

Application time per iteration in a back-to-back batch, in microseconds; lower is better. Each timing links to its measurement. Inputs are selected explicitly in `results/inputs/<gpu>.json`; new files do not change selections automatically. Generated from existing results; no benchmarks are rerun.

**Direct** enqueues the baseline operations each iteration. **Graph** replays the same operations in a CUDA Graph. **Optimized** is the agentic optimized implementation (`*_sota.cu`), which may change kernels, data movement, and launch mode. Graph speedup = Direct / Graph; optimized speedup = Graph / Optimized.

The [spreadsheet](cuda_performance.xlsx) focuses on large workload application summaries for each GPU. Small workloads are retained only as RTX 3090 diagnostics. It also has supporting sheets for isolated latency, kernel comparisons, source files, GPU predictions, and compact NCU kernel summaries linked to all individual launches. NCU medians describe profiled launches, not application latency or total GPU utilization. Notes are brief; cell comments retain the full explanations. Single/batched timing ratios reflect scheduling and measurement conditions, not pure launch overhead.

All application timings include input and output transfers except llama2c, which uses device-resident data. Batch counts and run counts appear in the notes or latency sheets. Pending means the measurement is unavailable.
